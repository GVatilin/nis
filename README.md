# PagedAttention на CPU: непрерывное и страничное размещение KV-кэша

Задание: [P23 «PagedAttention: управление памятью KV-кэша»](https://distsys.ru/osukhoroslov/nis2/src/branch/main/project-tasks/p23-pagedattention.md)

В проекте сравниваем два способа размещения. Непрерывный аллокатор заранее занимает область под запрос, а страничный выдает блоки по мере роста последовательности; на одинаковом пуле проверим вместимость, фрагментацию и цену чтения на CPU.

Пока готовы прототип и технические проверки. Ко второй точке добавим обработчик авторегрессионных запросов и динамический пакет, после чего сможем измерить задержку всего прогона и проверить, помогает ли экономия памяти обслуживать больше запросов.

Основа проекта: W. Kwon et al., *Efficient Memory Management for Large Language Model Serving with PagedAttention*, SOSP 2023

## Запуск

Для запуска нужен Python 3.12 или новее. Версию NumPy берем из `requirements.txt`, а команды выполняем из корня репозитория, чтобы скрипт видел прототип и окружение `.venv`.

Быстрая проверка на Linux/macOS:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python prototype/check.py --skip-memory
```

Через Make:

```sh
make install
make check-fast
```

Полная проверка с пулом на 4 ГиБ:

```sh
make check
```

Для пула на 1 ГиБ:

```sh
make check MEM_GIB=1
```

Интерпретатор можно выбрать при установке окружения. Для Linux/macOS подойдет `make install PYTHON=python3.12`; без Make запускайте скрипт напрямую, убрав `--skip-memory` и при необходимости добавив `--mem-gib 1`.

При успехе скрипт возвращает код 0. В конце он печатает «итог: все проверки пройдены», а при расхождении с ожидаемым результатом перечисляет ошибки и завершает работу с кодом 1.

Проверка памяти заполняет оба массива K/V. Так мы заставляем ОС выделить физические страницы и измеряем рост пикового RSS; если свободно меньше примерно 6 ГиБ, уменьшаем пул или выбираем быстрый запуск.

Время чтения зависит от конкретной машины. Фиксированного порога для этого замера нет: он показывает стоимость среза и сборки блоков на текущем компьютере, но сам по себе не доказывает ускорение обработчика.
